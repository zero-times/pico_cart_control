# Pico BLE 稳定性：断线取证与安全重连

本指南对应固件 `0.2.1`。手机继续通过 BLE 控制小车；USB 只用于诊断，不作为第二控制通道。
默认手动超时是 `timeout_ms=1200`。心跳超时后先进入软停止，再把 PWM 收到 0；急停和前障碍
仍然立即停车。重连后保持 `idle`，不会自动继续行驶。

## 已确认的本地原因

| 现象 | 本地可观测证据 | 处理 |
|---|---|---|
| `motor` 试转卡住主循环 | 命令处理期间不再轮询 STATE / stop / keepalive | 试转改为非阻塞；断连、stop、急停和超时都能立刻停车 |
| 导出挤占停车命令 | 手机队列里 `hwlog dump` 仍在写时，stop 排在后面 | Android 与微信都把 `stop` 插到队首，并清掉待发运动/保活 |
| 重连后半行或旧命令残留 | Pico RX 半行、手机待发 drive/keepalive | 断开时清空 Pico UART 缓存和手机命令队列 |
| STATE 短抖动 | Pico `ble_disconnect` 后立刻又 `ble_connect` | STATE 变化做 80ms 去抖；真实断开仍远早于 1200ms 超时 |
| 手机 GATT 失败 | Android `status=133` / 微信 `errCode` | 界面和日志记录系统错误码；原因无法确认时标为未知 |

MTU 协商失败不再当作连接失败。Android 优先请求 MTU 64；失败时退回默认 ATT 长度，仍按 18 字节分包。

## 断线时序

1. 手机 GATT 断开或 Pico `STATE=0` 去抖确认。
2. Pico 立即 `stop`，记录 `ble_disconnect cause=unknown` 或后续可确认原因；当前无法区分手机主动断开、距离过远和模块内部复位。
3. 手动模式默认 `timeout_ms=1200` 后触发软停止；这是心跳丢失的备份，不是第一停车路径。
4. 电机 PWM 归零还有斜坡时间，验收时分别记录触发时刻和 `pwml/pwmr` 到 0 的时刻。
5. 重连后 Pico 保持 `idle`。必须重新发送 `manual`/`drive`/`motor` 才允许运动。

## 手机操作

Android 调试页和微信首页都会显示连接状态及最近一次系统错误码。主动断开后手动重连：

1. 确认 Pico 心跳或 `status` 回包恢复。
2. 查询 `param`，确认 `timeout_ms=1200`。
3. 点动一次，再主动断开；车应停车且重连后不自动续跑。
4. 导出日志时按急停，导出应让路给 `stop`；中断的导出按不完整处理，恢复后可重新导出。
